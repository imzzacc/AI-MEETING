## 检索修复及边界

[v3 基线](retrieval-v3-baseline.json)在实际编译 Java 上执行，20 题完整来源命中 14 题。4 个无关问题、4 种不支持版本及不相关岗位均正确拒绝。这个基线包括 s15 对未知数据库的比较题，预设目标为 MySQL 资料；它没匹配时关闭知识追问是合理的保守处理，不能为提高数字而扩大版本适用范围。

v4 新增可审计的 `aliasGroups`：一组内所有词必须同时出现，多组之间满足任意一组即可。例：`Java + 对象 + hash(`、`MySQL + SERIALIZABLE`、`缓存 + 热门 + 过期`。同时保留原单词别名；没有词组字段的旧冻结目录按空列表恢复。仅从题目匹配，不从用户回答修改题库。

负例覆盖 Java Serializable 接口、文件哈希、浏览器缓存有效期、热门商品库存等，避免仅加宽泛关键词。修复后的同集重放是回归，不再称独立检索验收。来源正文、评分点和模型输入契约本次未改；因此没有为词组修复重复花钱跑 60 次模型。

实际编译 Java 的 [v4 回归](retrieval-v4-regression.json)完整来源命中 **19/20**；唯一未命中为 s15。四主题分别 5/5、5/5、4/5、5/5，4个无关负例、4种不支持版本及不相关岗位均正确拒绝。完整 Maven 验证163项单元/服务+6项真实Mongo IT，无失败/错误/跳过；新目录回读和缺少词组字段的旧记录回读均经过真实Mongo。运行中的应用仍为此前版本，本结果不冒充已部署的v4浏览器E2E。

资料适用性的版本过滤依赖结构化 scope；它不是对题面提及任意产品的语义保证。只有四个主题，不支持的内容仍正常问主问题并关闭知识追问。
