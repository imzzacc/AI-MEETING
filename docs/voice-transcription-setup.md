# 语音回答配置与排障

语音回答链路为浏览器麦克风 → 本项目 WebSocket → 讯飞实时语音转写大模型 → 回答框。面试工作流能评分或出题，并不代表语音服务已配置。

## 运行配置

在讯飞开放平台控制台进入自己的应用，找到“实时语音转写大模型”服务，核对服务权限和剩余额度。当前后端连接 `office-api-ast-dx.iflyaisol.com/ast/communicate/v1`；不要拿只有其他语音产品权限的配置替代。

从该应用复制 APPID、APIKey、APISecret，在后端进程环境中分别设置：

```dotenv
XUNFEI_APP_ID=
XUNFEI_API_KEY=
XUNFEI_API_SECRET=
```

只在仓库外保存实际值，不提交 Git，也不在聊天、截图或日志中公开。Docker Compose 从 `.env` 传入环境；直接 `java -jar` 不会自动读取 `.env`，应通过启动脚本导入环境后重启对应后端。`XUNFEI_RTA_API_KEY` 不能替代以上三项。修改面试工作流的 API_FLOW_ID 不会修复语音服务。

## 浏览器验收

1. 使用 localhost 或 HTTPS 打开前端，登录，在一场可答题的面试中点击“开始语音回答”。
2. 允许麦克风权限。连接期间显示“正在连接语音识别”，真正开始采集后显示“正在倾听中”。
3. 说一句短句，确认回答框连续出现文字；点击“停止语音回答”，确认已有文字保留且可编辑。再试一次，确认不会覆盖原草稿。
4. 若出现服务未配置提示，检查**正在运行的后端进程**的三项环境变量；若显示权限/额度问题，核对讯飞所选服务；若权限被拒绝，在浏览器地址栏的网站权限中允许麦克风。不要为排障自动购买或充值。

“正在倾听”表示本地采集和服务端转写上下文已启动，不保证供应商已接收有效语音。完整成功标准必须是实际说话后回答框出现正确文字；模拟 WebSocket 返回不能替代真实 ASR 验收。
