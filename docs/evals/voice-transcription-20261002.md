# 语音回答排障记录（2026-10-02）

状态：前端故障处理已修复；真实讯飞识别尚未恢复，缺少有效运行配置。不能以本记录中的模拟成功代替真实语音验收。

## 复现与原因

在个人本地前端 `localhost:5174` 使用合成测试账号登录，点击与面试共用的 SmartComposer 麦克风按钮。浏览器收到真实后端 `connected`，随后收到 `error: Transcription failed: Large-model realtime ASR requires appId/apiKey/apiSecret`。输入框保持空白，页面没有任何可见错误。此次复现没有创建新面试，也没有调用评分/出题模型。

运行后端未传入语音识别所需的三个环境变量；原本机开发目录和原虚拟机 `.env` 中这三项仍是占位值，不能直接恢复。面试工作流配置不会自动填充 `xunfei.lat-key`。

代码还存在启动顺序问题：WebSocket 一打开就发送缓存音频，早于 `start_transcription`/`transcription_started`；打开后的连接断开未通知录音状态；麦克风权限延迟返回时可能遗留采集流。

## 修复

- 主回答框显示中文错误，区分缺配置、服务权限/额度、麦克风权限、无设备、设备占用和连接失败。
- 等待服务端转写上下文确认，再启动麦克风；开始命令发出前及确认前不发送音频。
- 启动连接十秒超时退出，连接中可取消；拒绝重复启动，忽略已销毁连接的迟到回调。
- 连接断开时结束录音并保留已有回答；显式恢复 AudioContext，取消后归还迟到的麦克风流。
- 增加 [配置说明](../voice-transcription-setup.md)，强调直接启动 JVM 不自动加载 `.env`。

后端代码和个人运行 JAR未更换，因此此前注册登录修复仍然有效。本分支从 `main` 创建，不含另一个注册修复分支的提交。
